# Falcon WhatsApp Sender

Terminal-first WhatsApp message sender using whatsapp-web.js.

It is designed for SSH/server usage with no browser UI and prints QR in terminal for initial linking.

## Features

- Send WhatsApp text messages from terminal.
- Works with your personal WhatsApp account (linked session).
- Supports `.env` defaults and CLI overrides.
- Can generate message text using Gemini AI for `npm run send`.
- Includes server deployment automation with cron setup via `npm run deploy`.

## Requirements

- Node.js 18+
- Internet access from server
- A phone with WhatsApp to scan QR on first login

## Quick Start

1. Install dependencies:

```bash
npm install
```

1. Send a message:

```bash
npm run send -- 1234567890 "Hello from server"
```

On first run, scan the QR shown in terminal:
WhatsApp -> Linked devices -> Link a device.

## Number Format

- Use international format digits only.
- `+` is optional.
- Remove trunk `0` after country code.

Examples:

- Correct: `1234567890`
- Also accepted input: `+49 12345 67890` (auto-normalized)

## Configuration

Copy `.env.example` to `.env` and adjust values if needed.

Environment variables:

- `WA_SEND_TO`: target for sending, either phone number (`1234567890`) or chat/group name (`Saved Messages`)
- `WA_DEFAULT_PROMPT`: preferred default AI prompt from `.env`
- `WA_USE_AI_RESPONSE`: when `true`, message body is generated by Gemini from the prompt
- `GEMINI_FAILURE_MESSAGE`: fallback text sent if every Gemini attempt fails (instead of sending raw prompt)
- `WA_SEND_ATTEMPTS`: WhatsApp send retries for transient `sendMessage` failures (default: `4`)
- `WA_SEND_RETRY_DELAY_MS`: back-off between send retries in ms (default: `3000`)
- `WA_KEEP_ALIVE`: when `true`, keeps WhatsApp logged in after sending (default: `true`)
- `WA_INIT_DEBUG`: enables verbose startup diagnostics (default: `true`)
- `WA_AUTH_CLIENT_ID`: optional auth session id (unset by default)
- `WA_HEADLESS`: `true` or `false` (default: `true`)
- `WA_PUPPETEER_EXECUTABLE_PATH`: optional full path to system Chromium/Chrome binary
- `WA_PUPPETEER_LAUNCH_TIMEOUT_MS`: Puppeteer browser launch timeout in ms (default: `120000`)

- `GEMINI_API_KEY`: required for AI-generated list
- `GEMINI_MODEL`: primary model (default `gemini-2.0-flash`)
- `GEMINI_BACKUP_MODEL`: backup model tried after the primary is exhausted
- `GEMINI_TIMEOUT_MS`: per-attempt Gemini request timeout in ms (default: `60000`)
- `GEMINI_PRIMARY_ATTEMPTS`: tries on the primary model (default: `5`)
- `GEMINI_BACKUP_ATTEMPTS`: tries on the backup model (default: `2`)
- `GEMINI_RETRY_DELAY_MS`: back-off between Gemini attempts in ms (default: `2000`)
- `WA_SERVER_HOST`: remote SSH host
- `WA_SERVER_PRIVATE_KEY_PATH`: SSH private key path used by deploy script
- `DEPLOY_PATH`: remote path where repository is cloned/updated
- `GITHUB_TOKEN`: token used by deploy script for clone/pull

## One-Click Run in VS Code

This project now includes VS Code run configs in `.vscode/launch.json`.

- Open Run and Debug (`Ctrl+Shift+D`).
- Select one of:
  - `Falcon: Send Message (.env defaults)`
  - `Falcon: Send Message (prompt)`
- Click the green Run button.

Task shortcuts are also available in `.vscode/tasks.json`:

- `Falcon: npm run send`
- `Falcon: npm run check`
- `Falcon: Deploy to Server + Set Cron`

## Server Deployment

`npm run deploy` runs `deploy.sh`, updates the repo on the server, installs dependencies, sets cron, and uploads `.env`.

## Troubleshooting

- If stuck on startup, stop stale processes and rerun:

```bash
pkill -f "send.ts|tsx|chrome|chromium|puppeteer" || true
npm run send -- 1234567890 "retry test"
```

- If self-send works but other number does not, verify recipient has active WhatsApp and is not blocked.
- The sender prints the final outgoing message text (AI or fallback) before sending.

### Send to Number or Group/Chat

Use one variable only:

1. Set `WA_SEND_TO=1234567890` for a number, or `WA_SEND_TO=Saved Messages` for a chat/group name
2. Set your prompt in `WA_DEFAULT_PROMPT`
3. Run `npm run send`
